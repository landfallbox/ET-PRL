冷站运行工况随季节更替、负荷变化与设备老化持续漂移，是非平稳环境。在这种环境下，离线训练一次、部署后固定的静态策略必然随时间退化：旧数据上学到的最优行为，在新工况下不再是优的。这是所有静态策略的通病，不区分方法。

训练结束之后，两个组件都冻结了：控制策略 π 离线训练一次，部署后不再随工况漂移更新；触发阈值 τ 只对异常分数分布做统计跟踪，机制参数离线标定，不依据控制效果反馈学习。

第一篇回答了"何时更新更省"，没有回答"策略与触发机制本身怎么随长期工况漂移持续适应"。这两个一次性组件，恰好构成自迭代最自然的两个对象：这篇要让它们在闭环经验里持续进化。

检索覆盖 72 篇论文，五个方向都是空白。

1. 自迭代 RL 全部集中在 LLM、机器人与蛋白设计域，没有建筑能源控制。
2. 冷站 RL 期刊侧确认全是静态策略，非平稳靠多策略档案、变化点检测加多模型切换、退化触发再学习、数字孪生重训应对，没有闭环自迭代。
3. 自适应阈值在冷站侧已有规则式方案，但没有作为 RL 控制回路的一部分在线自迭代调整。
4. 事件触发 RL 在建筑与冷站域自 2022 年以来没有新工作。

独占交叉点是：真实冷站数据上的闭环自迭代，同时进化控制策略与事件触发阈值。

同时要承认一个前提风险：整篇动机建立在"静态策略在非平稳工况下确实退化，且退化足够明显"之上。这个前提目前是论证加旁证，还没在我们自己的数据上验证过，这正是 Phase 0 要做的事。

内层完整沿用第一篇的事件触发预测型 DQN，不动；外层套一个自迭代环，每轮四步：

部署，用当前策略与触发机制控制冷站，收集在线运行经验；

触发判断，依据在线经验判断是否需要启动一次更新，避免固定周期盲目重训；

更新，用部分或选择性方式更新策略与触发机制，不全量重训，防止遗忘与漂移；

再部署，把更新后的策略与触发机制放回控制回路。

触发机制从"只跟踪分数分布的统计自适应"升级为"依据控制效果反馈学习的可进化阈值"，与控制策略作为回路的一部分共同更新。

| 做法 | 触发谁能学 | 特点 |
|---|---|---|
| 可学习标量阈值 | 阈值是一个数，自迭代环每轮调一个数 | 最简单、最易归因，阈值在变一眼可见，倾向作基线 |
| 状态相关触发策略 | 阈值是一个状态到触发概率的函数 | 表达力强，不同工况不同灵敏度，倾向作扩展或消融 |
| 触发并入动作空间 | 由 agent 自己决定是否更新 | 最 RL 原生，但不再有显式阈值，贡献表述要改写，远期形态 |

主对比：自迭代对静态策略、对离线重训、对多策略档案与变化点切换、对规则式自适应阈值。

消融：去掉阈值更新、去掉锚定正则、固定周期迭代。
