1 · 最小定义（先记住这一句）

RSI 不是一个有教科书定义的固定技术，而是一个机制家族。它的本质是一个环：

部署当前的自己 → 收集自己的经验 →（由自己的性能触发）更新自己 → 再部署
π₀ → π₁ → π₂ → …   （冷站场景：π₀,τ₀ → π₁,τ₁ → …，阈值 τ 共同进化）

注意：它不是可以脱离论文先学懂的固定算法——读 RLoop / SELFI / ProteinZero 这些论文，本身就是"弄懂 RSI"的过程。你能先建立的，是下面这张概念锚。

2 · RSI 是"在线部署方式"吗？（一个易混点）

不完全是。RSI 是一种学习范式（策略如何随时间改进），不是部署方式。但它依赖部署——部署是必要前提，不是本质。

为什么"依赖部署"：RSI 的定义性特征是自指性——经验和改进信号必须来自 agent 自己的部署。不部署就没有自己的经验，也就没有自迭代（区别于离线 RL：静态数据训一次就完事）。所以部署阶段是 RSI 的"原料来源"。

但它也不是"在线 RL"。三者的差别在"更新时机"：

范式与部署的关系更新时机
离线 RL部署一次，无环部署前训完，之后不再更新
在线 RL部署中每步都更新（连续梯度）
RSI部署中（轮次式）离散结构化轮次：部署→收集→判断→更新→再部署

RSI 和在线 RL 的差别：在线 RL 每步都改；RSI 是"部署一段、攒一批经验、再做一次结构化更新"。RSI 的本质是那个"改进环"，不是部署本身——部署只是环里"收集经验"那一步的实现方式。

对冷站论文的关键推论：我们只有历史数据（没有实时现场接入），那 RSI 里的"部署"指什么？答案是 滚动窗口回放（rolling replay / 仿真回放）——在某个时间窗上"部署" πₖ、跑完这段数据、从结果收集经验，判断→更新→移到下一个窗"部署" πₖ₊₁。这正是文档反复强调"滚动评估协议"的原因：它就是历史数据上让"部署"阶段真实化的机制。

形态"部署"阶段靠什么何时做
历史数据版滚动回放 / 仿真现在就能做（Phase 0 动机实验）
现场版真实系统在线运行最终形态，需现场接入

一句话：RSI 是"部署耦合的迭代学习范式"——部署是入场券，改进环才是本体；在历史数据上，"部署"退化为滚动回放，所以滚动评估协议不是可选项，而是 RSI 在冷站数据上成立的承重墙。

关键：③ 是事件触发的——"自迭代"区别于"定期重训"的核心，也是它区别于"逐步在线学习"的核心（离散轮次 vs 连续更新）。

4 · 让它"自迭代"的三个特征（划界锚点）

① 自指性

经验与改进信号都来自 agent 自己的部署——不是人、不是教师、不是固定数据集。

冷站：用部署后自己跑出来的数据改进自己

② 迭代性（离散轮次）

改进发生在结构化轮次里，πₖ → πₖ₊₁，每轮建立在上轮之上，不是一次训练。

冷站：每个时间窗（日/工况周期）是一个轮次单元

③ 结构化更新步

每轮更新是一个 deliberate 步骤（筛轨迹→微调），不是逐步梯度更新。

冷站：筛成功轨迹 → RFT 微调 + KL 锚定

5 · 和邻近范式划界（读论文时归类的锚）

范式更新什么由什么驱动数据来源
离线 RL策略固定数据集预采集、静态
在线 RL策略持续交互实时环境，逐步更新
持续/终身学习策略/模型新任务流新任务不断到达
Meta-RL元策略任务分布多任务
自迭代 RSI策略（它自己）自己的经验 + 自己的性能自己的部署

最微妙的一对是 在线 RL vs 自迭代：在线 RL 每步都更新；自迭代是离散、结构化的改进轮次。事件触发的外层环正是让它"迭代"而非"只是连续在线学习"的东西——你之前感到的"事件触发 vs RL 冲突"，在这里被消解：触发不是冗余外力，它是"迭代"二字的构成部分。

时序逻辑显式（τ）+ 控制律学习（π），关注点分离。四个不冗余的理由：① 连续动作空间下 hold 不自然，ETC 干净处理；② 样本效率（π 只学"该动时做什么"）；③ τ 显式、可解释、可独立学/共同进化（新论文贡献的前提）；④ 执行/物理成本（冷机启停磨损）是一等约束。代价：引入了归纳偏置——审稿人会问"为什么不让 RL 隐式学"。

Adaptive ETRL (2409.19769) 的路线：把累积奖励增广进状态，价值函数天然编码历史，无需显式学触发条件即得自适应非平稳策略。它证明了"触发条件可学"成立——是新论文的桥，也是审稿人攻击"显式阈值不必要"的弹药。关键：走隐式路线就失去"阈值共同进化"这个贡献点。

理论定位一句话：事件触发不是替 RL 做它做不到的事，而是把 RL 本可以隐式学的时序逻辑，抽出来做成显式、可学、可共同进化的参数——代价是归纳偏置，收益是样本效率 + 可解释性 + 一个隐式触发给不出的贡献点。最干净的理论外壳是 SMDP：触发时刻做决策，触发间开环演化；"hold 作为动作"是 sojourn time 恒为 1 步的特例（Applied Energy 2020 即用 SMDP 框架）。

9 · RSI 和训练阶段：不是"参与训练"，是"治理生命周期"

RSI 不是训练算法——怎么训 = RFT 微调，不变。它是决定何时训、用什么训、怎么初始化的调度器 / 生命周期协议。原 ET-PRL 的"训练 → 部署 → 冻结"是一次性生命周期，RSI 把它变成重复生命周期。

两层更新：事件触发真正改的是什么

第一层 · 轮次内（不变）

π 用标准 RL（梯度下降）在当前轮数据上训练。RSI 不改变这一步——轮次内算法和原 ET-PRL 完全一样。

第二层 · 轮次间（新增）

事件触发：性能退化 ∨ 工况漂移 → 决定是否开下一轮。下一轮的数据 = 部署的 πₖ 收集的经验；下一轮的起点 = πₖ（热启动，不从零开始）。

两个易错点修正：① "每时间步都更新"是在线 RL 的特征，不是基线——事件触发在轮次级，不在时间步级；② 是"按需"（事件触发），不是"始终在线"。

10 · 价值边界：RSI 到底买到了什么（关键自检）

"10000 条数据"思想实验：如果数据是静态历史、环境是平稳的，那么 RSI ≈ 把一次训练拆成多次——没有价值。RSI 的价值由两个假设买来：

假设 ① 非平稳性

环境 / 工况随时间变化 → 顺序适应让最新工况赢得话语权。一次性全量训练 = 各工况的折中模型（"四季折中"模型）。

假设 ② 在策略自产数据

每轮数据由模型自己的动作产生——环境必须能评估"模型自己动作"的奖励。静态历史数据做不到：奖励固定在数据里，模型动作不影响奖励。

静态历史数据两个假设都不满足（或只弱满足 ①）→ 纯静态数据 RSI 是只保留顺序适应的弱化版。第 7 节闸门问题验证 ①（承重墙）；第 11 节验证 ②（环境选择）。

11 · 前置条件：环境必须"对模型自己的动作有响应"

静态历史数据序列是数据集，不是环境。RSI 要发挥作用，环境必须能对模型自己的动作返回奖励。四条路径：

路径非平稳性在策略奖励说明
真实在线部署✔✔真实冷站响应 agent 动作；竞赛数据不支持
物理仿真器✔（回放时间线）✔EnergyPlus 等；需建冷站模型
学习型数字孪生✔✔（保真度是天花板）训练代理模型当环境；接数字孪生文献线
纯静态历史数据弱✘仅保留顺序适应的弱化版

推荐路径：滚动回放过仿真器——历史时间线按序回放（→ 非平稳）+ agent 出动作、仿真器返奖励（→ 在策略），同时满足两个假设。保真度风险 = RSI 链天花板：OOD 动作 → 仿真器预测不准 → 在错误奖励上自迭代，越迭代越偏；对历史数据校验仿真器 / 置信度加权是前置。

12 · 拼出的冷站 RSI 环（设计骨架，待 Phase 0 验证）

# 外层环（RSI，事件触发）
初始化：π₀, τ₀ = ET-PRL 策略 + 离线贝叶斯阈值   ← 前一篇结果作为起点，不丢弃
循环：
  1. 部署 πₖ + τₖ，一个时间窗内收集在线经验
  2. [迭代触发判断]（事件触发，非固定周期）：
       性能退化？（奖励/KPI 跌破基线）
       工况漂移？（运行分布变化）
       都不满足 → 保持 πₖ+τₖ 继续部署（不迭代）
  3. 触发则更新（部分式，不丢历史）：
       筛成功轨迹 → RFT 微调 πₖ → πₖ₊₁（KL 锚到 πₖ，防漂移/过特化）
       同步更新 τₖ → τₖ₊₁（显式可学阈值，与 π 共同进化）
  4. 再部署 πₖ₊₁ + τₖ₊₁
安全：KL 锚定 + 安全盾（参照 CQD-ERL），防止自迭代把策略带崩

待 Phase 0 回答的前置问题（上面第 7 节的动画就是它的预演）：① 冷站数据上"静态 π₀+τ₀ 随时间退化"是否真实成立（价值边界 · 假设 ①，第 10 节）——不成立则外层环无动机，需先定位非平稳性来源（工况漂移 / 设备老化 / 使用模式变化）；② 环境能否提供在策略奖励（价值边界 · 假设 ②，第 11 节）——确定滚动回放过仿真器 / 数字孪生的路径。
